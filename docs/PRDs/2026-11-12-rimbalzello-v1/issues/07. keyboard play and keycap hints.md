# keyboard play and keycap hints

## PRD

[2026-11-12-rimbalzello-v1](../prd.md)

## What to build

The laptop becomes a keyboard instrument: the keyboard bindings' intents drive the app (play/stop, tempo with repeat, held loop zones, set anchor, return, mutes, pad undo, nudge and fine nudge, hint toggle). A run of arrow nudges is one pad move for undo.

Keycap hints: small grey outlined keys next to each control (`designs/06-laptop-shortcuts-shown.png` for the look; its tempo and help keys are outdated, use `,` `.` and `?`). On light backgrounds (held loop zone, return button) they invert to black. With hints shown, the pad corner reads `nudge ←↑↓→  shift fine`. Hidden by default; `?`, `h` or `// help` toggles them on non-touch layouts, and the choice is remembered. The footer reads `// help ?` so players find them.

Keys never steal focus from text inputs, and focused buttons still respond to space and enter as buttons (decide and document how space-as-play coexists with a focused button; simplest reading: space plays/stops unless a button or input has focus).

## Acceptance criteria

- [ ] Playwright at 1280×800: space starts and stops; holding `.` raises bpm repeatedly; `q` mutes bd; holding `2` while playing engages 1/8 and releasing ends it; `a` then a pad change then `r` restores the pad at the next bar; three arrow presses then `z` restore the position from before the run.
- [ ] Playwright: `?` shows keycap hints, reload keeps them shown, `h` hides them; `// help` toggles them too.
- [ ] Layout rule checks pass at 1280×800 with hints shown.

## Notes from earlier reviews

- From the keyboard review, decide: what arrows and space do while a strip or button has focus; the keyup macOS drops for keys pressed while Cmd is held (a key can stick); `?` needs Shift+/ and does nothing on a Swiss layout (`h` still works).
