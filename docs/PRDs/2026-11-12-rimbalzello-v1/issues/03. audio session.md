# audio session

## PRD

[2026-11-12-rimbalzello-v1](../prd.md)

## What to build

The audio session module that makes the app dependable on an iPhone, extending the tracer's tap-to-play unlock.

- In the `▶ tap to play` gesture: create and resume the AudioContext; set `navigator.audioSession.type = 'playback'` where it exists, otherwise start a silent looping `<audio>` element in the same gesture, so the silent switch does not mute the app. Sample rate is not forced.
- Resume after interruptions (calls, app switches, `visibilitychange`, the context's `statechange` to `suspended` or `interrupted`). When resume is refused, show a visible `tap to resume` over the pad in place of `▶ tap to play`; one tap resumes.
- Hold a Screen Wake Lock while playing; release on stop; re-acquire after the page becomes visible again.
- Feature-detect everything; browsers without these APIs keep working.

Checking it on a real iPhone (silent switch, calls, lock) is part of the device acceptance issue.

## Acceptance criteria

- [ ] Playwright (Chromium): suspending the AudioContext from the page and refusing resume shows `tap to resume`; tapping it resumes and hides it.
- [ ] Playwright: after `▶ tap to play` a wake lock is requested where the API exists, and released after stop (stubbed API is fine).
- [ ] With `navigator.audioSession` stubbed, its type is `playback` after the tap; without it, a looping silent `<audio>` element is playing.
- [ ] No errors in browsers lacking `audioSession` or `wakeLock` (Firefox, WebKit projects).
