# setup store with anchor and pad undo

## PRD

[2026-11-12-rimbalzello-v1](../prd.md)

## What to build

The framework-free store the UI and transport subscribe to. It holds the setup (x, y, chaos, densities, per-drum sound, drift, drive, swing, bpm), the mutes, the anchor snapshot and the pad's undo slot.

- **Anchor**: captures the setup minus tempo (pattern, sound, swing, drift, drive). On load the anchor is the loaded setup, so return before any set anchor restores the start setup. The anchor is not kept across reloads. Applying an anchor never touches tempo or mutes. When the return lands is the transport's job; the store only exposes "the setup to restore".
- **Pad undo**: one slot, flip/flop. A pad move is a committed position change (a tap, a whole drag, a fine adjust, a run of arrow nudges); the caller says when a move begins and ends. Undo swaps the current position with the slot; undoing again redoes. Pad only: nothing else is undoable.
- **Device memory**: the last setup is saved to localStorage (all access in try/catch, storage failures are silent) and offered on load. Mutes and anchor are not saved. Choosing between URL hash and stored setup belongs to the URL hash issue; this store only loads and saves.
- Subscribers are notified on change; the store has no UI import.

## Acceptance criteria

- [ ] Tests: setting an anchor, changing pattern, sound, swing, drift, drive, tempo and mutes, then applying the anchor restores the first five and leaves tempo and mutes as changed.
- [ ] Tests: applying the anchor before any set anchor restores the setup the store was created with.
- [ ] Tests: pad move A→B then undo returns to A; undo again returns to B; a non-pad change between does not enter the undo slot.
- [ ] Tests: a saved setup round-trips through storage; a throwing or missing localStorage does not throw out of the store.
