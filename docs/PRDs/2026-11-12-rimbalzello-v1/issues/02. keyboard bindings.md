# keyboard bindings

## PRD

[2026-11-12-rimbalzello-v1](../prd.md)

## What to build

A pure module: key down/up events (`event.code`, `repeat`, `shiftKey`) in, intents out. Bound by physical position, designed for the US layout:

| Key | Intent |
| --- | --- |
| space | play / stop |
| `,` `.` | tempo down / up (the only keys that act on repeat) |
| `1` `2` `3` `4` held | loop 1/4, 1/8, 1/16, 1/32 |
| `a` | set anchor |
| `r` | return on next bar |
| `q` `w` `e` | mute bd, sd, hh |
| `z` | pad undo / redo |
| arrows | nudge the pad; shift + arrows fine nudge |
| `?` (Slash with shift) or `h` | toggle keycap hints |

- Loop hold semantics: the zone key pressed most recently wins; releasing it falls back to another still-held zone key; the loop ends when no zone key is held.
- A run of arrow nudges counts as one pad move: emit a move-begin on the first nudge and a move-commit when the run ends (end of run = no arrow held, or a tunable idle gap).
- Hint visibility is remembered in localStorage (try/catch), hidden by default.
- Events from text inputs are ignored.

Wiring the intents to the app is the keyboard play issue.

## Acceptance criteria

- [ ] Tests: each binding by `event.code`, including that a Swiss or AZERTY `key` value with the US `code` still maps to the same intent.
- [ ] Tests: repeated keydown is ignored for everything except `,` and `.`.
- [ ] Tests: hold `1`, press `3`, release `3` gives zones 1/4 → 1/16 → 1/4; release `1` ends the loop.
- [ ] Tests: three arrow presses in a run produce one committed pad move; shift + arrow uses the fine step size.
- [ ] Tests: hint visibility persists across module instances and survives a throwing localStorage.
