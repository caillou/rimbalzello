# url codec

## PRD

[2026-11-12-rimbalzello-v1](../prd.md)

## What to build

A pure setup ↔ URL hash codec. The hash is `v1.` plus base64url of 21 bytes in the fixed order from the PRD's URL format table (x, y, chaos, densities bd sd hh, bd freq punch tone decay level, sd freq tone snappy decay level, hh level, drift, drive, bpm, swing). bpm is stored as the bpm value (60–200), swing as the percentage (50–75). Mutes and anchor are excluded.

- Out-of-range bpm or swing clamp on decode.
- A wrong length, bad base64 or an unknown version decodes to the default setup.
- Structure the decoder by version so a later `v2.` appends fields and keeps the `v1.` decoder.

Writing the hash into the address bar (rate limit, `replaceState`) is the URL hash issue, not this one.

## Acceptance criteria

- [ ] Tests: any valid setup round-trips exactly.
- [ ] Tests: a hand-built 21-byte payload decodes each byte into the field the PRD's table names (catches a byte-order change, which would break shared links).
- [ ] Tests: bpm 30 and 250 clamp to 60 and 200; swing 40 and 90 clamp to 50 and 75.
- [ ] Tests: 20 or 22 bytes, invalid base64, `v9.` and an empty hash all give the default setup.
