# pad gesture interpreter

## PRD

[2026-11-12-rimbalzello-v1](../prd.md)

## What to build

A pure state machine: timestamped pointer events (down, move, up, with pointer id and pad-relative position) in, intents out. It owns all gesture timing in milliseconds and knows nothing about steps or audio.

Intents:

- **jump** to an absolute target, emitted on the first finger down at once (no waiting for a double-tap window);
- **follow** the finger during a drag;
- **fine** relative movement at about ¼ speed from the current position (double-tap and slide);
- **revert** the first finger's move when a second finger lands within the two-finger window (not recorded as a move);
- **undo** on a completed two-finger tap;
- **move committed** when a tap, a whole drag or a fine adjust ends, so the setup store records exactly one pad move.

Implement the state table in `design.md` (Pad interaction) as written: states idle, touching, dragging, second touch, fine, two fingers. Movement threshold, double-tap window and distance, two-finger window and fine-adjust speed go in the tunables module.

## Acceptance criteria

- [ ] Tests with synthetic timestamped events (no real timers) for each row of the state table in `design.md`.
- [ ] Tests: a tap emits jump on the down event, before any up; a drag emits one committed move, not one per move event.
- [ ] Tests: a second finger within the two-finger window emits revert, and lifting both with little movement emits undo; moving past the threshold with two fingers emits neither undo nor a committed move.
- [ ] Tests: double-tap and slide moves at the tunable fraction of finger travel, relative to the current position; a double-tap without movement acts as a tap.
