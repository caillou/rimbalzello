# Review summary: what to decide and change

Merged from `review-fable.md`, `review-opus.md`, `licence-research.md`, `swing-research.md`, plus `pending-decisions.md`. Status column is filled in as decisions are taken.

| # | Topic | Source | Finding | Status |
| --- | --- | --- | --- | --- |
| 1 | Step resolution | Fable (verified upstream) | A Grids step is a **32nd note**; 32 steps = **1 bar**. Docs assume 16ths / 2 bars. Return, swing, looper sizes (→ 8/4/2/1 steps), step display all change. | fact, fix |
| 2 | Engine | both | Native voices "tuned by ear" are untestable for agents. Port Peaks drums (MIT) to TS in an AudioWorklet, golden WAVs from the C++ build; run the transport in the worklet (sample-accurate, no main-thread jitter, no hidden-tab collapse). | **decided: native Web Audio voices for v1.** Sound direction will move (hard techno); Peaks is a starting point, not the target. Voices sit behind a **kit** interface so other kits (or a worklet Peaks port) can be loaded later. Mitigations: transport stays a pure, clock-injected state machine (portable into a worklet later); lookahead ~100 ms; OfflineAudioContext smoke tests (renders, not silent, no clipping, hits at expected times). |
| 3 | Phone heights | both (blocker) | Mockups use full screen heights; Safari's visible area is ~150–180 px less. `<760 px` puts nearly every iPhone in the short layout; SE gets a ~125 px pad. Short sound mode undesigned. Size against real viewports, add a compact layout, ship a web manifest for full-height home-screen launch. | **decided: design against real browser heights** (`100dvh`, measured Safari/Chrome viewports), recompute breakpoints, add a third **compact** layout for the smallest case (SE in Safari), and design short/compact sound mode. No web manifest in v1. Needs a design pass with screenshots. |
| 4 | iOS audio | both | Silent switch mutes Web Audio (`navigator.audioSession.type = 'playback'` or silent `<audio>` fallback), resume after interruptions, screen lock / wake lock, first-launch "tap to start" undesigned. | **decided: all in v1.** Playback audio session (`navigator.audioSession.type = 'playback'`, silent `<audio>` fallback); auto-resume after interruptions, visible "tap to resume" when refused; Wake Lock while playing; first launch shows the play screen with a big `▶ tap to play` over the pad, one tap starts audio and groove. Test on a real iPhone. |
| 5 | Licence | all three | Map is GPL-3.0-or-later (Émilie Gillet sole holder); Peaks MIT. Split now: own code MIT, one GPL map module, built app ships GPL; ask Émilie for MIT; fallback own map. Regenerate Euclidean table. Don't fetch the map at runtime to dodge. Ship MIT + OFL (Plex) notices; source link to deployed commit. | **decided: everything GPL-3.0-or-later.** README notes MIT as a possible later step (sole author can relicense once the map is replaced or permitted). Dependency rule: permissive / LGPL / GPL-3-compatible only; no GPL-2.0-only, no unlicensed or non-commercial (incl. future sample packs). Regenerate the Euclidean table; ship third-party notices (OFL for Plex); about's source link points at the deployed commit. Asking Émilie stays optional. |
| 6 | Tap latency vs silent undo | both | Waiting for the double-tap window delays every tap 250–500 ms (3–4 steps). Alternatives: two-finger tap undo, an undo button, or accept latency. Gesture state machine undefined. | **decided: taps act immediately (glide starts at once); undo = two-finger tap** (one step, flip/flop); double-tap-and-slide stays fine adjust; laptop undo key `z` (to confirm with keyboard-layout point 12). Hint teaches the two-finger tap. Gesture state machine to be specified in design.md. |
| 7 | Mutes reachability | both | Mutes unreachable in fx tab, sound mode, landscape. Proposal: step-display labels (bd sd hh) are the mute toggles everywhere. | **decided: step-display labels are the only mute toggles** (≥44 px hit area); muted line goes grey, label struck through; strip labels no longer mute; keys `q w e` unchanged. |
| 8 | Grids port details | Opus (verified) | 5×5 map is a permutation of nodes (`drum_map[5][5]`); interpolation relies on 8-bit wraparound; RNG advances per evaluation. Make the generator pure with perturbations passed in; transport re-rolls at the real playhead's step 0, not the looped one. | accept |
| 9 | Testing / feedback loop | both | Agents can't hear or see. One `tunables` module for all by-ear values; Playwright for layout (no scroll, 44 px, screenshots) and an audio smoke test; name toolchain, CI, deploy trigger. | **decided: one `tunables` module** for every by-ear value (commented); **Playwright rule checks** at each target viewport (play screen never scrolls, controls ≥44 px, no overlap), no screenshot comparison yet; offline audio smoke test; **GitHub Actions CI blocks the deploy** on failure. |
| 10 | Unspecified edge cases | both | Looper (start quantisation, slide rules, interaction with return), anchor before first set and across reload, URL byte layout and versioning, tempo range, Safari `replaceState` rate limit. | **looper: copy the reference hardware looper** using the behaviour spec in `looper-research.md` as written (sizes 8/4/2/1 steps; start on the heard step; slide keeps start and stays in step with the playhead; release slips; all drums; only while playing; accents repeat as looped). Undocumented points implemented as proposed and iterated after trying it. Vendor names stay out of prd.md, design.md, CONTEXT.md and screenshots. Other edge cases **decided**: tempo 60–200 bpm, default 128; return before any set anchor restores the start setup; anchor not kept across reload (resets to current setup); ~~last setup remembered on device, a URL hash always wins~~ (superseded by #18: nothing is remembered on the device, and the bare address opens with the default setup); URL: fixed byte order per version written into the PRD, broken links fall back to default, ≤1 hash update per second; chaos re-rolls at the real playhead's pattern start, not on loop wrap. Vendor names may remain in `reviews/` research files as source citations only. |
